# PICO-8 для Karabas Go / Mini / Mini G — план

## Исходные данные (обзор 2026-11-17)

- Готового FPGA-ядра PICO-8 нет нигде (MiSTer, MiST, Analogue Pocket — только просьбы на форумах 2020–21).
  PICO-8 — рантайм Lua, а не процессор: ядро = софт-CPU + Lua VM + API PICO-8 (+ аппаратные помощники).
- Программная основа: **fake-08** (MIT, C++, jtothebell/fake-08 814991a, подмодуль `upstream/fake-08`),
  внутри **z8lua** (форк Lua 5.2, числа 16.16 fixed point, FPU не нужен). Звук из zepto-8.
  Сам PICO-8 проприетарный: только чистая реимплементация, картриджи — от пользователя.
- CPU: VexRiscv (MIT), готовые Verilog-варианты litex-hub/pythondata-cpu-vexriscv
  (Min — без кэша rv32i; Lite — I$ 2K; стандартный — rv32im, I$ 4K + D$ 4K; IMAC — со сжатыми командами). sbt / java не нужны.
- Плата: XC6SLX25, SRAM 4 MB (2M x16, асинхронная), SDRAM 32 MB, RP2040 (занят прошивкой, не хост рантайма).
- Бюджет PICO-8: виртуальный CPU 4–8 MHz (wiki: 2^22 тактов/с), большинство операций Lua ≈ 1 такт;
  т.е. «полная загрузка» ≈ 70–140 тыс. операций VM на кадр 1/60 с.

## Ф0 — замеры (go / no-go), без платы, видео и звука

1. **Нагрузка на хосте** (`src/bench`, fake-08 без экрана): операции Lua VM на кадр, время, доля VM / рисования / звука.
2. **Цена операции в Verilator**: SoC VexRiscv + модель шины с реальным циклом SRAM (16 бит, такты как `archie_sram.v`),
   короткий Lua-бенчмарк, такты на операцию VM: без кэша и с I/D-кэшем в BRAM. Прогоны — секунды.
3. **Площадь и Fmax**: XST + один PAR Mini G (`-t 2`), выводы SRAM в IOB.

Результат Ф0: таблица «кадров/с на картридж на конфигурацию» + строка go / no-go.

Выводы:
- **Звук**: синтезатор fake-08 на float/double стоит больше всей игры (celeste: +134 мкс к 65). На rv32im без FPU это

  ускорители не помогают, всё решают такты на операцию VM на нашем CPU (Ф0.2).

### Ф0.2 — цена на soft-CPU (2026-11-17)

Инструменты (`src/fw`, `src/sim`):
- `src/fw`: fake-08 + картридж в образе SRAM под rv32im (xPack riscv-none-elf-gcc 15.2.0-1, newlib + libstdc++),
  `make CART=... [FRAMES] [OPS_HOOK=1]`. Тот же ввод и сид, что у хостового бенчмарка; совпадение с хостом проверено (ниже).
- `src/sim/iss`: свой быстрый RV32IM ISS (~35 MIPS), модель кэшей (direct-mapped, строка 32 байта), профиль (`prof.py`),
  дамп на кадре K с заглушкой возобновления (`--dump-at`).
- `src/sim/tb_soc`: Verilator, настоящий VexRiscv на модели SRAM 2M x16 (полслова за обращение; I и D делят шину),
  старт с дампа ISS (`--rv 0x3ff000`) — кадры без 45 млн тактов init. Verilator ~1.3 MHz.
- `src/sim/run_f02.sh`: весь замер одним запуском (хост, проверка, ISS по трём кэшам), `predict2.py` — прогноз.

Что пришлось починить в сборке под rv32 (не в upstream, флагами в `src/fw/Makefile`):
1. **`luaV_execute` в z8lua fake-08 собран с `optimize("O0")`** (2022, обход бесконечных циклов у максимума fix32 =
   UB знакового переполнения). Лечение: `-fwrapv` + копия `lvm.c` без атрибута. psychik 15.6 → 5.9 млн инструкций на шаг.
   Тест `test/carts/loop_max_val.p8` завершается.
2. **int32_t = long в newlib** → fix32 переводил индексы в int через double (soft-float). Сделали int32_t = int.
3. **Ошибки / yield Lua через C++ throw** — раскрутка стека каждый кадр (~14 %) и `.eh_frame` без регистрации (abort).
   Теперь `LUA_USE_LONGJMP` (в fake-08 нет catch), `.eh_frame` регистрируется при старте.
4. Остаток: **API fake-08 пишет `int x = lua_tonumber(...)`** — неявный `operator double()`, на rv32 soft-float:
   3–25 % инструкций (столбец soft-fp). Чинится правкой API при портировании.
5. **Ошибка upstream z8lua (и у Sam Hocevar тоже): `sin_helper` читает `sintable[0x1000]`** — за концом таблицы
   из 4096 элементов — для углов, кратных 0.25 (`sin(0.25)`, `cos(0)`…): мусор, разный на разных платформах.
   Правильное значение там 0 (`sin(0.25) = -1`). Исправлено копией `lpico8lib.c` (`src/fw/sinfix.sh`) в прошивке и хост-бенчмарке.

**Проверка правильности** (`src/sim/run_f02.sh` + `check_host.py`): хост (`bench-v`) против rv32 в ISS (`VERIFY=1`),
480 шагов на картридж, одинаковый фиксированный сид `rnd` и сид хеша строк Lua (иначе порядок `pairs()` разный —
сид в Lua 5.2 смешивает адреса и время). **10 картриджей из 10: число операций Lua и хеш экрана совпадают на каждом шаге.**
Кадры 120 / 240 / 479 (montage): в игре — celeste, 8_legs_to_love, aasteroids, just_one_boss, rhythmfrog, thndrbld;
psychik — демо-эффект; **nuke, buns, birds_with_guns остались в меню** (их цифры — меню, не геймплей); vampire не загрузился.

Калибровка в Verilator (VexRiscv как сгенерирован: rv32im, I$ 4K, D$ 4K write-through), кадры 100–129 celeste, 100–103 psychik:

| | идеальная память | SRAM rd 1 / wr 3 | SRAM rd 2 / wr 2 |
|---|---:|---:|---:|
| celeste CPI | 2.46 | 3.76 | 4.67 |
| psychik CPI | 2.55 | 4.25 | — |

Модель `cycles = 1.85·instr + (I$miss + D$miss)·line + stores·st` сходится со всеми прогонами Verilator
(базовый CPI 1.7–2.0 при любой памяти). Сверка с `archie_sram.v`: чтение там конвейерное (строка дешевле, чем в модели стенда),
запись 3 такта (75 нс) на полслова — в прогнозе запись 75 нс.

**Прогноз** (`src/sim/predict2.py`; шаги 60–480, без хука; игровой кадр = 2 шага у 30-кадровых игр;
«среднее / p95» = доля реального времени в среднем и на 5 % самых тяжёлых кадров):

| картридж | fps | soft-fp | рисование | млн инстр. на кадр | **M** измерено: 4K/4K, 40 MHz | E1: 16K/16K, 40 | E2: 32K/16K, 80 MHz | E3: E2 + буфер записи − soft-fp |
|---|---:|---:|---:|---:|---|---|---|---|
| just_one_boss | 30 | 3 % | 60 % | 0.54 | 71 / 53 % | 88 / 70 | 149 / 116 | 209 / 163 |
| celeste | 30 | 6 % | 55 % | 1.10 | 34 / 24 % | 43 / 31 | 73 / 52 | 105 / 76 |
| 8_legs_to_love | 30 | 12 % | 37 % | 1.62 | 20 / 12 % | 28 / 16 | 49 / 28 | 72 / 41 |
| rhythmfrog | 60 | 14 % | 15 % | 0.82 | 19 / 19 % | 28 / 28 | 47 / 47 | 74 / 73 |
| buns (меню) | 60 | 12 % | 20 % | 1.21 | 13 / 12 % | 18 / 16 | 30 / 27 | 44 / 40 |
| nuke (меню) | 60 | 13 % | 63 % | 2.29 | 10 / 8 % | 12 / 10 | 22 / 19 | 31 / 26 |
| birds_with_guns (меню) | 60 | 5 % | — | 3.30 | 5 / 5 % | 6 / 6 | 13 / 12 | 18 / 18 |
| aasteroids | 60 | 25 % | — | 3.46 | 5 / 4 % | 6 / 5 | 12 / 10 | 21 / 17 |
| thndrbld | 60 | 19 % | 13 % | 3.02 | 5 / 5 % | 7 / 7 | 13 / 12 | 19 / 18 |
| psychik | 60 | 15 % | 1 % | 5.57 | 3 / 3 % | 4 / 4 | 7 / 7 | 11 / 11 |

Что измерено, а что нет: **M** — единственная конфигурация, откалиброванная в Verilator. E1–E3 — экстраполяция модели:
VexRiscv с кэшами 16–32K надо сгенерировать заново (sbt / java), 80 MHz не проверены (Ф0.3), буфер записи и чистка
soft-float в API fake-08 — работа порта. Доля рисования — по профилю инструкций; полный RTL-движок рисования дал бы
грубо ×1/(1 − доля): celeste E3 ≈ 230 / 170 %, 8_legs ≈ 115 / 65 %, nuke ≈ 85 %, rhythmfrog ≈ 85 %, thndrbld ≈ 22 %, psychik ≈ 11 %.

Выводы Ф0.2:
- В измеренной конфигурации в реальном времени не идёт ни один картридж (лучший — just_one_boss, 71 %).
- Даже со всеми улучшениями CPU (E3) в реальном времени только самые лёгкие (just_one_boss, celeste в среднем);
  обычные 2D — 40–75 %, тяжёлые / 3D — 10–20 %.
- С полным RTL-движком рисования (+ синтезатор в RTL) лёгкие и часть обычных 2D-игр пойдут; игры, упирающиеся в Lua VM
  (thndrbld, psychik, aasteroids, rhythmfrog частично), — нет: цена операции Lua ≈ 110 инструкций × CPI ~2 на нашем CPU.
- Итог: **no-go для «PICO-8 вообще»**. Возможен только «плеер лёгких 2D-картриджей», и то ценой большой работы:
  VexRiscv с большими кэшами (sbt), RTL-рисование, RTL-синтезатор, правка API fake-08, буфер записи, Fmax 80 MHz.
